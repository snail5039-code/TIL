## 👍 좋아요 기능 예시 코드 및 보완점
### 1. 데이터베이스 설계 (DB)
좋아요를 위한 테이블은 **어떤 사용자가** \*\*어떤 게시물(또는 대상)\*\*에 좋아요를 눌렀는지를 저장해야 합니다.

| **테이블 명** | **TBL_LIKE** |
| --- | --- |
| **컬럼** | `like_id` (PK, 자동증가) |
|  | `post_id` (FK, 게시물 ID) |
|  | `user_id` (FK, 사용자 ID) |
|  | `liked_at` (좋아요 누른 시간) |

### 2. 백엔드 (Java/Spring 아키텍처 예시)
좋아요를 누르거나 취소하는 요청을 처리합니다.
### 2.1. DAO (Data Access Object)
Java
```java
// LikeDAO.java
// DB에 직접 접근하여 좋아요 상태를 확인하고 변경합니다.

@Repository
public class LikeDAO {

    // 1. 좋아요 상태 확인 (사용자가 이미 눌렀는지 확인)
    public int checkLikeStatus(int postId, int userId) {
        // SELECT COUNT(*) FROM TBL_LIKE WHERE post_id = ? AND user_id = ?
        // 결과가 1이면 이미 좋아요 상태, 0이면 좋아요 아님
        return sqlSession.selectOne("like.checkStatus", Map.of("postId", postId, "userId", userId));
    }

    // 2. 좋아요 추가
    public int insertLike(int postId, int userId) {
        // INSERT INTO TBL_LIKE (post_id, user_id) VALUES (?, ?)
        return sqlSession.insert("like.insert", Map.of("postId", postId, "userId", userId));
    }

    // 3. 좋아요 삭제 (취소)
    public int deleteLike(int postId, int userId) {
        // DELETE FROM TBL_LIKE WHERE post_id = ? AND user_id = ?
        return sqlSession.delete("like.delete", Map.of("postId", postId, "userId", userId));
    }

    // 4. 게시물의 전체 좋아요 수 카운트
    public int countLikesByPostId(int postId) {
        // SELECT COUNT(*) FROM TBL_LIKE WHERE post_id = ?
        return sqlSession.selectOne("like.countByPostId", postId);
    }
}
```

### 2.2. Service (비즈니스 로직)
Java

```java
// LikeService.java
// 좋아요/취소 로직을 수행하고, 최종 좋아요 개수를 반환합니다.

@Service
public class LikeService {

    @Autowired
    private LikeDAO likeDAO;

    // 좋아요를 토글(추가/삭제)하고, 변경된 총 좋아요 수를 반환
    public Map<String, Object> toggleLike(int postId, int userId) {
        int status = likeDAO.checkLikeStatus(postId, userId);
        String action = "";

        if (status > 0) {
            // 이미 좋아요 상태 -> 좋아요 취소 (DELETE)
            likeDAO.deleteLike(postId, userId);
            action = "DELETED";
        } else {
            // 좋아요 상태 아님 -> 좋아요 추가 (INSERT)
            likeDAO.insertLike(postId, userId);
            action = "INSERTED";
        }

        // 최종 좋아요 개수 카운트
        int likeCount = likeDAO.countLikesByPostId(postId);

        // 결과 반환 (JSON 응답을 위해 Map 형태로 구성)
        return Map.of("action", action, "likeCount", likeCount);
    }
}
```
### 2.3. Controller (요청 처리)
Java
```java
// LikeController.java
// 클라이언트의 AJAX 요청을 받아 Service로 전달합니다.

@Controller
@RequestMapping("/api/like")
public class LikeController {

    @Autowired
    private LikeService likeService;

    // POST /api/like/toggle 요청을 처리
    // @ResponseBody: 메서드가 반환하는 객체를 HTTP 응답 본문(Body)으로 직접 사용 (JSON 변환)
    @PostMapping("/toggle")
    @ResponseBody
    public Map<String, Object> toggleLike(@RequestParam("postId") int postId, HttpSession session) {
        // 🚨 보완점: 실제 서비스에서는 세션/인증을 통해 userId를 안전하게 가져와야 합니다.
        // 현재는 예시를 위해 userId를 임의로 1로 설정
        Integer userId = (Integer) session.getAttribute("LOGIN_USER_ID");
        if (userId == null) {
             // 401 Unauthorized 처리
             return Map.of("error", "로그인이 필요합니다.");
        }

        // Service 호출 및 결과 반환
        return likeService.toggleLike(postId, userId);
    }
}
```

### 3. 프론트엔드 (JSP와 비동기 처리)
JSP 파일에서 \*\*JavaScript의 `async`/`await`\*\*를 사용하여 좋아요 요청을 비동기적으로 처리합니다.
HTML
```java
<script>
    // postId는 현재 페이지의 게시물 ID라고 가정
    const postId = 123; // 예시 게시물 ID

    // 좋아요 버튼 클릭 이벤트 핸들러
    document.getElementById('like-button').addEventListener('click', () => {
        handleLikeToggle(postId);
    });

    // 💡 async/await를 사용한 비동기 요청 처리 함수
    async function handleLikeToggle(postId) {
        const likeButton = document.getElementById('like-button');
        const countDisplay = document.getElementById('like-count');

        // 요청 전 버튼 비활성화 (보완점 1: 중복 요청 방지)
        likeButton.disabled = true;

        try {
            // 🚀 비동기 요청 시작
            const response = await fetch('/api/like/toggle', {
                method: 'POST',
                headers: {
                    'Content-Type': 'application/x-www-form-urlencoded'
                },
                // 데이터를 application/x-www-form-urlencoded 형식으로 전송
                body: `postId=${postId}`
            });

            // 응답이 성공적인지 확인
            if (!response.ok) {
                throw new Error('서버 응답 오류');
            }

            // 💡 await: JSON 응답을 파싱할 때까지 기다립니다.
            const result = await response.json();

            // UI 업데이트
            countDisplay.textContent = result.likeCount;
            if (result.action === 'INSERTED') {
                likeButton.textContent = '💖 좋아요 취소';
            } else if (result.action === 'DELETED') {
                likeButton.textContent = '🤍 좋아요';
            }

        } catch (error) {
            console.error('좋아요 처리 중 오류 발생:', error);
            alert('좋아요 처리에 실패했습니다. 잠시 후 다시 시도해주세요.');

        } finally {
            // 요청 완료 후 버튼 다시 활성화
            likeButton.disabled = false;
        }
    }
</script>

<div>
    <span id="like-count">15</span>명이 좋아합니다.
    <button id="like-button">🤍 좋아요</button>
</div>
```

## 🛠️ 추가 보완할 점

| **영역** | **보완 사항** | **설명** |
| --- | --- | --- |
| **DB / DAO** | **트랜잭션 관리** | `toggleLike` 서비스 메서드 내에서 좋아요 확인, 추가/삭제, 카운트 작업이 **하나의 트랜잭션**으로 묶여야 합니다. (Spring의 `@Transactional` 어노테이션 사용) |
| **Controller** | **보안 및 인증** | `userId`는 반드시 세션, JWT 등 **인증된 사용자 정보**에서 가져와야 하며, 클라이언트에서 임의로 조작할 수 없어야 합니다. |
| **Frontend** | **낙관적 업데이트** | 요청이 성공할 것을 예상하고 **응답을 기다리지 않고** 버튼 UI와 카운트를 먼저 변경하고, 실패 시에만 되돌리는 **낙관적 업데이트**를 적용하면 사용자 경험이 훨씬 빨라집니다. |
| **Frontend** | **중복 요청 방지** | 사용자가 버튼을 빠르게 두 번 눌러서 요청이 두 번 가는 것을 막기 위해, 요청 처리 중에는 버튼을 **비활성화**해야 합니다. (위 예시에 반영됨) |
| **JSP** | **렌더링** | JSP는 이제 화면 템플릿으로만 사용하고, 비즈니스 로직 없이 **View**의 역할만 수행하도록 유지하는 것이 좋습니다. |
