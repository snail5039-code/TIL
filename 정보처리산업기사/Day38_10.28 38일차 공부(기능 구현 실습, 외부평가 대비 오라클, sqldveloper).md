## 💾 Oracle 18c XE 및 SQL Developer 설치 가이드
### 1. Oracle 18c XE 설치
Oracle 18c XE(Express Edition)는 학습용으로 무료로 사용할 수 있는 경량 데이터베이스입니다.
1. **다운로드:** Oracle 공식 웹사이트에서 **Oracle Database 18c Express Edition**을 다운로드합니다. (다운로드를 위해 Oracle 계정이 필요하며, 로그인이 필요할 수 있습니다.)
2. **설치 준비:** 다운로드한 ZIP 파일의 **압축을 해제**하고, 내부의 `setup.exe` 파일을 **관리자 권한으로 실행**합니다.
3. **설치 진행:**
	- 설치 마법사의 안내에 따라 \*\*'다음'\*\*을 클릭하여 진행합니다.
	- 라이센스 동의 후 설치 경로를 설정합니다. (⚠️ **주의:** 설치 경로에 **한글**이 포함되지 않도록 합니다.)
	- **SYSTEM 계정 비밀번호**를 설정하는 단계가 나옵니다. 이 비밀번호는 데이터베이스 관리자 계정으로 사용되므로, 반드시 기억할 수 있는 비밀번호를 입력하고 설치를 완료합니다.
> 💡 참고: 설치 과정 중 시간이 다소 오래 걸릴 수 있으며, 방화벽 관련 알림이 나오면 액세스를 허용해 줍니다.

### 2. SQL Developer 설치
SQL Developer는 Oracle 데이터베이스를 관리하고 SQL을 실행할 수 있는 **GUI 환경의 툴**입니다.
1. **다운로드:** Oracle 공식 웹사이트에서 **Oracle SQL Developer**를 다운로드합니다. 보통 **JDK가 포함되지 않은 버전**을 다운로드하는 경우가 많습니다.
2. **설치:** SQL Developer는 **별도의 설치 과정 없이** 압축 해제 후 바로 실행할 수 있는 **포터블(Portable)** 형태입니다.
	- 다운로드한 ZIP 파일의 압축을 원하는 경로에 해제합니다.
	- 압축을 푼 폴더 내의 `sqldeveloper.exe` 파일을 실행합니다.
	- 만약 처음 실행 시 **JDK 경로**를 묻는 창이 나타나면, 설치된 JDK 폴더의 경로를 지정해 줍니다.
3. **DB 접속 설정:**
	- SQL Developer 실행 후, **왼쪽 상단의 '+' (새 접속)** 아이콘을 클릭합니다.
	- **접속 정보**를 입력합니다:
		- **접속 이름:** 원하는 이름 (예: `Oracle_XE_SYSTEM`)
		- **사용자 이름:** `SYSTEM` (Oracle 설치 시 생성된 최고 관리자 계정)
		- **비밀번호:** Oracle 18c XE 설치 시 설정했던 비밀번호
		- **호스트 이름:** `localhost` (본인 PC에 설치한 경우)
		- **포트:** `1521` (기본값)
		- **SID:** `XE` (18c XE 기본값)
	- **'테스트'** 버튼을 눌러 \*\*'상태: 성공'\*\*이 뜨면, \*\*'접속'\*\*을 클릭하여 데이터베이스에 연결합니다.

## 💻 웹 애플리케이션 개발 흐름 (게시판 예시 기반)
요청하신 게시판 기능을 웹 애플리케이션으로 개발하는 일반적인 흐름은 다음과 같습니다. 이 흐름은 \*\*클라이언트(브라우저)\*\*와 **서버(애플리케이션 서버, 데이터베이스)** 간의 상호작용을 나타냅니다.
### 1. 화면 요청 및 조회 (게시판 접속 및 상세보기)

| **단계** | **클라이언트 (브라우저) 역할** | **서버 (애플리케이션/DB) 역할** |
| --- | --- | --- |
| **게시판 접속** | 웹 서버에 게시판 목록 페이지 요청 (GET) | DB에서 게시글 목록을 조회하여 HTML/데이터 생성 후 응답 |
| **로그인** | 로그인 정보(ID/PW)를 서버로 전송 (POST) | DB에서 사용자 정보 확인 및 **세션** 생성 후 응답 |
| **상세보기 요청** | 특정 게시글 번호와 함께 상세보기를 요청 (GET) | **게시글 번호**로 DB에서 해당 내용을 조회하여 HTML/데이터 생성 후 응답 |

2. 게시글 수정 흐름

| **단계** | **클라이언트 (브라우저) 역할** | **서버 (애플리케이션/DB) 역할** |
| --- | --- | --- |
| **수정 버튼 클릭** | **수정 버튼** 표시 여부 확인 (작성자 여부) 후, 수정 요청 (GET) | DB에서 기존 내용을 가져와 **`form`**** 태그**가 포함된 수정 입력 페이지를 생성하여 응답 |
| **수정 내용 입력** | `input`, `textarea` 태그를 통해 제목, 내용 등을 입력 | (입력만 진행, 서버로 전송하지 않음) |
| **수정 버튼 클릭** | **`form`****에 담긴 데이터** (제목, 내용, 게시글 번호)를 서버의 **적절한 서블릿/컨트롤러**로 전송 (**POST** 또는 PUT) | **DB**에서 해당 게시글의 내용을 **UPDATE** 처리 |
| **처리 완료** | 알림창으로 **"수정되었습니다."** 메시지를 확인 | DB 처리 후, **알림창 스크립트**와 함께 **상세보기 페이지로 이동**할 것을 응답 |

3. 게시글 삭제 흐름

| **단계** | **클라이언트 (브라우저) 역할** | **서버 (애플리케이션/DB) 역할** |
| --- | --- | --- |
| **삭제 버튼 클릭** | JavaScript의 `confirm()` 함수를 사용하여 **"정말로 삭제하시겠습니까?"** 알림창 표시 | (아직 서버에 요청 전) |
| **'확인' 선택 (삭제 진행)** | 삭제 요청(게시글 번호 포함)을 서버로 전송 (**POST** 또는 DELETE) | **DB**에서 해당 게시글을 **DELETE** 처리 |
| **처리 완료** | 알림창으로 **"삭제되었습니다."** 메시지를 확인 | DB 처리 후, **알림창 스크립트**와 함께 **게시판 목록 페이지로 이동**할 것을 응답 |

**💡 ****`confirm()`**** 사용 시점:**
게시글 삭제 버튼 클릭 시, 서버에 요청을 보내기 **직전**에 클라이언트(브라우저)에서 `confirm()` JavaScript 함수를 호출하여 사용자에게 한 번 더 확인합니다.
- 사용자가 \*\*'확인'\*\*을 누르면, **삭제 요청**을 서버로 전송합니다.
- 사용자가 \*\*'취소'\*\*를 누르면, **요청을 중단**하고 아무 일도 일어나지 않습니다.
