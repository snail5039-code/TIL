## 1. 웹 동작의 흐름 및 3요소
### 1.1. 웹의 3요소 (핵심 구성 요소)
웹 서비스를 구동하는 데 필수적인 핵심 요소 세 가지입니다.

| **요소** | **풀 네임** | **역할** | **예시 소프트웨어 (언급된 것)** |
| --- | --- | --- | --- |
| **웹 서버 (Web Server)** | - | 클라이언트(브라우저)의 **정적 콘텐츠** 요청 처리 및 **WAS로 요청 전달** | **nginx**, **Tomcat** (WAS 기능도 내장 가능) |
| **WAS (Web Application Server)** | Web Application Server | **동적 콘텐츠** 요청 처리. 비즈니스 로직 수행, DB와의 연동 등 | **Tomcat** |
| **DB (Database)** | - | 데이터를 **저장, 관리, 검색**하는 시스템 | MySQL, Oracle, PostgreSQL 등 |

### 1.2. 웹 동작의 흐름 (네이버 접속 예시)
브라우저를 통해 사용자가 주소를 입력하거나 아이콘을 클릭하여 요청을 보낼 때, 웹 서비스가 응답을 생성하여 돌려주는 과정입니다.
1. **브라우저** \$\\rightarrow\$ **웹 서버**: 브라우저가 **요청**을 보냅니다. (주소 입력)
2. **웹 서버** \$\\rightarrow\$ **WAS**: 웹 서버는 요청을 수행할 수 있는 **WAS**에게 작업을 요청합니다.
3. **WAS** \$\\rightarrow\$ **DB** (필요시): WAS는 비즈니스 로직 수행 중 **데이터가 필요**하면 DB에 **데이터를 요청**합니다.
4. DB \$\\rightarrow\$ WAS: DB는 요청받은 데이터를 가공하여 WAS에 응답합니다.
	(데이터가 필요 없으면 3, 4단계는 생략)
5. **WAS** \$\\rightarrow\$ **웹 서버**: WAS는 데이터를 사용하여 임무를 수행하고 웹 서버에게 **최종 응답**을 돌려줍니다.
6. **웹 서버** \$\\rightarrow\$ **브라우저**: 웹 서버는 받은 응답을 최종적으로 **브라우저**에 돌려줍니다.
> 💡 전체 흐름:
	브라우저 \$\\rightarrow\$ 웹 서버 \$\\rightarrow\$ WAS \$\\rightarrow\$ (DB) \$\\rightarrow\$ WAS \$\\rightarrow\$ 웹 서버 \$\\rightarrow\$ 브라우저

## 2. 웹 서버 및 WAS 관련 기술
### 2.1. 포트 번호
- **HTTP**: 기본 포트 **80**
- **HTTPS**: 기본 포트 **443**
- **Tomcat 기본**: 기본 포트 **8080** (개발 환경에서 자주 사용)
### 2.2. Context Path와 URL 구조
웹 서버 환경에서 특정 애플리케이션에 접근하는 주소 구조입니다.

| **구성 요소** | **예시 값** | **담당 파트** | **설명** |
| --- | --- | --- | --- |
| `WebServer의IP` | `localhost` | **웹 서버** | 서버의 IP 주소 또는 도메인 |
| `:웹서버포트` | `:8080` | **웹 서버** | 웹 서버가 사용하는 포트 번호 |
| `/contextPath` | `/servletAM` | **웹 서버** | 웹 애플리케이션의 고유 이름 (루트 경로는 `/` 임) |
| `/servlet매핑url` | `/HomeServlet` | **WAS** | WAS 내부의 특정 **Servlet**으로 연결되는 매핑 주소 |

> 전체 URL 예시: http://localhost:8080/servletAM/HomeServlet
### 2.3. 개발 이슈 해결 (Clean)
"어제까지 아무 문제 없이 테스트를 했는 데 오늘 와서 해보려고 하니 서버가 안 켜져"와 같은 대표적인 개발 환경 문제를 해결하는 방법으로 **Clean** 작업이 있습니다. 이는 IDE(예: Eclipse) 내에서 프로젝트의 빌드 상태를 초기화하고 다시 빌드하는 과정으로, **불필요한 캐시나 잘못된 컴파일 결과**를 제거하는 데 효과적입니다.

## 3. Servlet 프로그래밍 및 요청 처리
### 3.1. 쿼리 스트링 (Query String)
클라이언트가 서버로 데이터를 보낼 때 URL 뒤에 \*\*`?`\*\*로 시작하며 **`key=value`** 형태로 데이터를 전달하는 방식입니다.
> 예시: .../HomeServlet?color=blue&limit=10&dan=7
### 3.2. Servlet 요청 처리 예시 (Java Code)
### 예시 1: 고정된 구구단 (5단) 출력
Java
```java
protected void doGet(HttpServletRequest request, HttpServletResponse response)
    throws ServletException, IOException {
    // 응답의 타입과 인코딩 설정 (HTML과 한글 처리를 위함)
    response.setContentType("text/html; charset=UTF-8");
    response.setCharacterEncoding("UTF-8");

    response.getWriter().append("== 5단 ==" + "<br>");
    for (int i = 1; i <= 9; i++) {
        int dan = 5;
        // 브라우저로 내용을 전송
        response.getWriter().append(dan + " * " + i + " = " + dan * i + "<br>");
    }
}
```

### 예시 2: 쿼리 스트링으로 입력받아 동적으로 구구단 출력 및 스타일 적용
이 코드는 `color`, `limit`, `dan` 3가지 **쿼리 스트링** 값을 받아서 구구단 단수, 반복 횟수, 그리고 출력 색상을 동적으로 변경하는 로직입니다.
Java
```java
protected void doGet(HttpServletRequest request, HttpServletResponse response)
    throws ServletException, IOException {
    response.setContentType("text/html; charset=UTF-8");
    response.setCharacterEncoding("UTF-8");

    // 1. 쿼리 스트링 값 읽기 및 기본값 설정
    // request.getParameter("파라미터명")으로 값 획득
    String color = request.getParameter("color");
    if (color == null || color.equals("")) {
        color = "black";
    }
    String inlimit = request.getParameter("limit");
    if (inlimit == null || inlimit.equals("")) {
        inlimit = "1"; // 기본 반복 횟수
    }
    String indan = request.getParameter("dan");
    if (indan == null || indan.equals("")) {
        indan = "1"; // 기본 단수
    }

    // 2. HTML 출력 (color 값으로 style 적용)
    response.getWriter().append(String.format("==  %s단 ==<style>body{color:%s}</style> <br>", indan, color));
    
    // 3. 문자열 형태의 limit, dan을 정수로 변환 후 구구단 계산 및 출력
    int limit = Integer.parseInt(inlimit);
    int dan = Integer.parseInt(indan);
    
    for (int i = 1; i <= limit; i++) {
        response.getWriter().append(String.format("%d * %d = %d<br>", dan, i, dan * i));
    }
}
```

### 예시 3: 인스턴스 변수를 이용한 카운터
이 예시는 `Servlet`의 **인스턴스 변수**가 요청 간에 유지된다는 특징을 보여줍니다. 즉, 여러 요청이 하나의 `i` 변수를 공유하며 접근할 수 있습니다. (이는 멀티스레드 환경에서 **Thread-Safe** 하지 않을 수 있으므로 주의해야 합니다.)
Java
```java
// 인스턴스 변수
private int i = 0; 

protected void doGet(HttpServletRequest request, HttpServletResponse response)
    throws ServletException, IOException {
    // 페이지에 처음 들어왔을 때 0이 나오고, 새로고침 시마다 값이 1씩 증가
    // i++는 출력 후 1 증가를 의미
    response.getWriter().append(String.format("%d", i++)); 
}
```

## 4. 웹 개발 디자인 패턴 및 기술
### 4.1. MVC 패턴 (Model-View-Controller)
웹 애플리케이션을 구조화하는 디자인 패턴입니다.
- **Controller (컨트롤러)**: **요청**을 받아 적절한 **Model**과 **View**를 연결하는 역할 (Servlet이 담당).
- **Model (모델)**: 애플리케이션의 **데이터**와 **비즈니스 로직**을 담당 (DB 연동, 데이터 처리).
- **View (뷰)**: 사용자에게 보여주는 **프레젠테이션** 영역 (HTML, JSP 등이 담당).
### 4.2. JSP (JavaServer Pages)
HTML 코드 내에 Java 코드를 삽입하여 **동적인 웹 페이지**를 생성할 수 있게 하는 기술입니다. WAS에서 실행되어 Servlet으로 변환된 후 응답됩니다.
### JSP 코드 예시
JSP에서는 \*\*스크립틀릿(`<% ... %>`)\*\*을 사용하여 자바 코드를 작성합니다.
A. HTML 태그와 함께 사용하는 경우 (반복 출력)
\<div\> 태그를 10번 반복해서 출력합니다.
Java
```java
<% for(int i = 0; i < 10; i++){ %>
    <div>안녕하세요</div>
<% } %>
```

B. 자바 문법만 넣을 경우 (로직 수행)
HTML을 출력하지 않고 단순히 자바 로직만 수행합니다.
Java
```java
<% for(int i = 0; i < 10; i++){  
    // 로직 수행 (예: DB에 데이터 삽입 등)
} %>
```

> JSTL (JSP Standard Tag Library): JSP 내에서 복잡한 자바 코드를 최소화하고 태그 형태로 로직을 구현할 수 있도록 돕는 라이브러리입니다. (JSP의 가독성과 유지보수성을 높이는 데 사용됩니다.)
