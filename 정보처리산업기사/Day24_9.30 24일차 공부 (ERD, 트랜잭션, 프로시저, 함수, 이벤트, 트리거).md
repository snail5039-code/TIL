## 데이터 모델링 및 설계의 핵심: ERD
- \*ERD (Entity-Relationship Diagram)\*\*는 데이터베이스 설계의 청사진입니다. 데이터베이스 내의 데이터 요소(개체)와 그들 사이의 관계를 시각적으로 나타내는 도구입니다.

| 개념 | 설명 |
| --- | --- |
| **개체-관계 다이어그램** | 'Entity-Relationship Diagram'의 약자. 데이터베이스 설계 시 사용되는 시각적 도구. |
| **목적** | 데이터베이스 내의 \*\*개체(테이블)\*\*와 **관계**를 한눈에 파악하고 도식화(Diagram)하여 설계의 논리적 구조를 확립합니다. |
| **논리적 설계** | 사람이 이해하기 쉬운 언어와 기호로 데이터 구조를 표현 (특정 DB 시스템에 종속되지 않음) |
| **물리적 설계** | 실제로 사용될 데이터베이스 관리 시스템(DBMS)에 맞게 데이터 타입, 인덱스 등을 구체화 (특정 DB 시스템에 종속됨) |

### 1. 개체(테이블) 관계 도식화 규칙
ERD에서 개체(테이블) 간의 관계를 표현할 때 사용되는 표기법을 정리했습니다. 주로 \*\*까마귀발 표기법(Crow's Foot Notation)\*\*을 사용합니다.

| 표기 요소 | 의미 | 예시 그림 | 관계 설명 |
| --- | --- | --- | --- |
| **관계선** | 실선 | — | 필수적인 관계 (반드시 참여해야 함) |
|  | 점선 | —— | 선택적인 관계 (참여하지 않아도 됨) |
| **관계 차수** | 직선 (하나) | — | '1'을 의미 (최소/최대 1개) |
|  | 까마귀발 (여러 개) | \< | '다(N)'를 의미 (최대 N개) |
|  | 동그라미 (선택) | ∘ | '0'을 의미 (최소 0개) |

### 테이블 관계 유형

| 유형 | 표기 | 설명 (예시) |
| --- | --- | --- |
| **1:1** | —— (양쪽 끝이 직선) | 한 사용자(1)는 하나의 계정 정보(1)를 가집니다. |
| **1:N** | —\< (한쪽은 직선, 다른 쪽은 까마귀발) | 한 교수(1)는 여러 명의 학생(N)을 가르칩니다. |
| **N:M** | \<\< (양쪽 끝이 까마귀발) | 여러 학생(N)은 여러 개의 강좌(M)를 수강할 수 있습니다. (※ 이 관계는 실제 DB에서 중간에 **중간 테이블**을 두어 1:N 관계로 해소해야 합니다.) |

## 2. 데이터베이스 고급 기능
단순히 테이블을 설계하는 것을 넘어, 데이터의 일관성을 유지하고 복잡한 작업을 효율화하기 위한 기능들입니다.

| 기능 | 설명 | 예시 (MySQL 기준) |
| --- | --- | --- |
| **트랜잭션 (Transaction)** | 여러 SQL 작업을 하나의 작업 단위로 묶어 실행하는 기능. \*\*전부 성공(Commit)\*\*하거나 \*\*전부 실패(Rollback)\*\*하여 데이터의 일관성을 보장합니다. | `sql START TRANSACTION; UPDATE Accounts SET Balance = Balance - 10000 WHERE AccountID = 1; UPDATE Accounts SET Balance = Balance + 10000 WHERE AccountID = 2; COMMIT; -- 또는 ROLLBACK;` |
| **프로시저 (Procedure)** | 미리 저장된 SQL 코드 블록. 복잡한 로직을 DB 내부에 저장하여 재사용하고 성능을 향상시킵니다. **값 리턴이 필수는 아닙니다.** | `sql DELIMITER // CREATE PROCEDURE GetUserInfo (IN user_id INT) BEGIN SELECT * FROM Users WHERE UserID = user_id; END // DELIMITER ;` |
| **함수 (Function)** | 값을 리턴하는 SQL 코드 블록. SELECT 문 등에서 값을 계산하거나 조작하는 용도로 사용됩니다. **반드시 값을 리턴해야 합니다.** | `sql DELIMITER // CREATE FUNCTION CalculateAge (birth_date DATE) RETURNS INT READS SQL DATA BEGIN RETURN TIMESTAMPDIFF(YEAR, birth_date, CURDATE()); END // DELIMITER ;` |
| **트리거 (Trigger)** | 테이블에 데이터 변경(INSERT, UPDATE, DELETE)이 발생 시 **자동으로 실행**되는 SQL 코드. 데이터 무결성 검사, 로그 기록 등에 사용됩니다. | `sql CREATE TRIGGER LogUserUpdate BEFORE UPDATE ON Users FOR EACH ROW INSERT INTO UserLogs (UserID, ChangeDate) VALUES (OLD.UserID, NOW());` |
| **이벤트 (Event)** | 일정 시간마다 자동 실행되는 작업 (스케줄러). 배치 작업, 통계 데이터 집계 등에 사용됩니다. | `sql CREATE EVENT DailyCleanup ON SCHEDULE EVERY 1 DAY STARTS '2025-01-01 03:00:00' DO DELETE FROM TempLogs WHERE LogDate < DATE_SUB(NOW(), INTERVAL 7 DAY);` |

## 3. 개발 협업을 위한 역할 정리
프로젝트를 성공적으로 완수하기 위해 각 역할자가 이해해야 할 핵심 협업 사항입니다.

| 역할 | 주요 업무 (프로젝트 기여) | 협업 시 핵심 포인트 |
| --- | --- | --- |
| **개발자** | 실제 서비스 기능 구현 (백엔드 로직, 프론트엔드 UI/UX, DB 연동) | **명확한 API 정의** 및 **DB 설계 검토** (속도, 유지보수 측면) |
| **디자이너** | 서비스의 시각적 요소(UI), 사용자 경험(UX) 설계 | **기술적 구현 가능성**과 **디자인의 효율성**에 대해 개발자와 지속적 소통 |
| **기획자** | 서비스의 목표 설정, 기능 정의, 요구사항 분석 (What to build) | **개발 일정 및 범위**를 명확히 하고, \*\*핵심 기능(MVP)\*\*에 집중하도록 가이드 |
