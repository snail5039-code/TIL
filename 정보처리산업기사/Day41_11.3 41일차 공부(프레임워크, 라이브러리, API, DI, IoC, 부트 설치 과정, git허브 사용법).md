## 💻 라이브러리, 프레임워크, API 핵심 정리
- **라이브러리 (Library):**
	- **개념:** 개발에 필요한 \*\*특정 기능들(도구)\*\*을 모아 놓은 집합체입니다.
	- **비유:** **기성복**과 같습니다. 개발자가 주도적으로 코드를 작성하며 필요할 때 라이브러리의 기능을 **가져다 쓰는** 방식입니다.
	- **제어권:** **개발자**에게 있습니다.
- **프레임워크 (Framework):**
	- **개념:** 소프트웨어 개발을 위한 **뼈대**나 기반 구조입니다. 전체적인 흐러름과 틀을 제공하며, 그 틀 안에 개발자가 코드를 넣어 완성합니다.
	- **비유:** **뼈대**나 건축 설계도와 같습니다. 프레임워크가 제공하는 규칙과 구조를 **따라야** 합니다.
	- **제어권:** **프레임워크**에 있습니다. (👉 **IoC** 개념과 연결)
- **API (Application Programming Interface):**
	- **개념:** 응용 프로그램에서 사용할 수 있도록 운영체제나 다른 프로그램이 제공하는 기능/규격입니다.
	- **비유:** **서버 개념**으로 이해하면 쉽게 다가갈 수 있습니다. 클라이언트(사용자)가 서버(API)에게 요청하면 서버가 응답을 주는 것처럼, 정해진 규격(함수/URL 등)을 통해 다른 시스템의 기능을 이용합니다.
	- **🌟 면접 단골 질문:** 라이브러리/프레임워크/API는 **면접에서 자주 출제되니 각 개념의 차이점과 예시를 명확히 공부**하는 것이 중요합니다.

## 🛠️ 스프링 핵심 개념 (DI, IoC, MVC)
### 1. DI (Dependency Injection, 의존성 주입)
- **개념:** 사용할 객체(의존 객체)를 직접 생성하거나 찾는 것이 아니라, 외부(주로 스프링 컨테이너)에서 **객체를 가져다가 사용**하도록 주입해주는 디자인 패턴입니다.
- **목적:** 코드의 재사용성을 높이고, 테스트하기 쉽게 만들며, 객체 간의 결합도를 낮춥니다.
- **주입 방식:**
	- **필드 주입 (Field Injection):** 전역 변수(필드)에 `@Autowired`를 사용하여 주입합니다. (**간편하지만, 테스트 어렵고 의존성 숨김 문제로 권장되지 않음**)
	- **생성자 주입 (Constructor Injection):** 생성자를 통해 주입합니다. (**가장 권장되는 방식**이며, 불변성 보장 및 순환 참조 방지 등의 장점)
	- **세터 메서드 주입 (Setter Method Injection):** 세터 메서드를 만들고 `@Autowired`를 사용하여 주입합니다. (**선택적인 의존성에 사용**되나, 런타임에 객체가 바뀔 수 있음)
### 2. IoC (Inversion of Control, 제어의 역전)
- **개념:** 객체의 생성, 생명 주기 관리 등을 **개발자가 직접 하지 않고, 스프링(프레임워크)이 알아서 만들고 관리**하는 것을 의미합니다.
- **프레임워크의 특징**을 가장 잘 나타내는 개념입니다.
- **스프링 빈 (Spring Bean):** **Spring이 알아서 만들고 관리해주는 객체**를 Spring Bean이라고 부르며, 이 빈들이 모여있는 곳을 **Spring Container**라고 합니다.
### 3. MVC (Model-View-Controller)
- **개념:** 애플리케이션의 역할을 세 가지(Model, View, Controller)로 나누어 설계하는 디자인 패턴입니다.
- **스프링 역할 분담:** 스프링에서 각 계층의 역할을 엄격하게 분리하여 사용합니다.
	- **Controller:** 사용자 요청 처리 및 Service 호출
	- **Service:** 비즈니스 로직 처리
	- **DAO (Data Access Object) / Repository:** 데이터베이스 접근 및 조작
### 4. 아키텍처 (Architecture)
- **개념:** 시스템의 **구조**와 구성 요소 간의 관계를 정의합니다.
- **🌟 추가 학습:** 스프링 애플리케이션의 \*\*전체 구조 (아키텍처)\*\*를 이해하고 **그려낼 수 있도록** 연습해야 합니다. (예: 3-Tier Architecture)

## ⚙️ 스프링 프로젝트 환경 설정 및 설치 과정
### 1. IDE 및 환경 설정
- **STS (Spring Tool Suite):** 현재 **4.28.0 버전을 사용 중**입니다.
	- **주의:** **STS 4.1X 버전대에서는 Lombok 설치 시 문제가 발생**하는 경우가 있으므로, 안정적인 최신 버전이나 LTS 버전을 사용하는 것이 좋습니다.
- **계정명 설정:** 프로젝트를 진행하는 사용자 계정에 **한글이 있으면 안 됩니다.** (인코딩 및 경로 문제 발생 가능) 계정을 **영어로 변경**하는 것이 좋습니다.
### 2. 필수 라이브러리 및 도구 설치 과정

| **항목** | **목적** | **설치/사용 시 주의사항 및 설명** |

| **Emmet** | HTML/CSS 자동 완성 및 간결한 코드 작성을 위한 플러그인 (VS Code 등) | IDE에 맞는 플러그인 설치 |

### 3. Spring Boot 설치 시 주의사항
- **`javax.`**** vs ****`jakarta.`**** 네임스페이스:**
	- **`javax.`**** (Java EE):** \*\*3.X 이전 버전들 (2.X \~\~)\*\*의 스프링 부트에서 사용되던 패키지 접두사입니다.
	- **`jakarta.`**** (Jakarta EE):** **3.X 이후 버전들**의 스프링 부트에서 사용되는 새로운 패키지 접두사입니다. (버전에 따라 의존성 이름이 다르므로 주의 필요)
### 4. 설정 파일
- **`yml`**** (YAML):** **YAML Ain't Markup Language**의 약자입니다. 속성들을 계층 구조로 표현할 때 가독성이 높아 **Spring Boot에서 설정 파일로 많이 사용**됩니다. (기존의 `properties` 파일 대체)

## 💻 스프링 개발 기본 (Controller, Mapping)
### 1. Spring Boot의 특징
- **Auto Configuration (자동 설정):** 필요한 빈들을 자동으로 설정해 줍니다. (설정 단순화)
- **Embedded Server (내장 서버):** Tomcat 등의 웹 서버가 내장되어 있어 별도의 설치가 불필요합니다.
- **Starter Dependency:** 관련 라이브러리들을 묶어 하나의 의존성으로 제공합니다.
### 2. Controller 기본 구조 및 매핑
주어진 코드를 바탕으로 \*\*`@Controller`\*\*와 **`@RequestMapping`** 및 \*\*`@ResponseBody`\*\*의 역할을 정리합니다.
- **`@Controller`****:** 해당 클래스가 **Controller** 역할을 한다는 것을 Spring에게 알려줍니다.
- **`@RequestMapping("/경로")`****:** 요청 경로와 메서드를 매핑합니다.
- **`@ResponseBody`****:** 메서드가 반환하는 값이 \*\*응답 본문(Response Body)\*\*이 된다는 것을 의미합니다.
	- **주의:** `@ResponseBody`가 없으면 반환 값 `"안녕하세요"`는 응답할 \*\*경로(View 파일명)\*\*로 인식됩니다.
- **`@GetMapping`**** / ****`@PostMapping`****:**
	- **`@GetMapping("/경로")`****:** HTTP **GET** 요청만 처리합니다. (데이터 조회에 사용)
	- **`@PostMapping("/경로")`****:** HTTP **POST** 요청만 처리합니다. (데이터 등록/수정에 사용)
	- **추가:** 하나의 URL에 대해 **GET/POST 매핑은 함께 존재할 수 있으며**, 요청 방식에 따라 다른 메서드가 실행됩니다.
### 예제 코드: `@RequestMapping`
Java
```java
package com.example.demo.controller;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.ResponseBody;

@Controller
public class UsrHomeController {
	
	@RequestMapping("/usr/home/main")
	@ResponseBody
	public String showMain() {
		return "안녕하세요";
	}
	
}
```

### 예제 코드: `@GetMapping` 및 파라미터 처리
URL: `http://localhost:8081/usr/article/write?title=asdasd&content=qweqwe`
Java
```java
package com.example.demo.controller;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.ResponseBody;

@Controller
public class UsrArticleController {
	
	@GetMapping("/usr/article/write")
	@ResponseBody
	public String write(String title, String content) { // 쿼리 스트링의 이름과 동일하게 변수명을 선언하면 자동으로 바인딩됩니다.
		System.out.println(title);
		System.out.println(content);
		
		return "write";
	}
	
}
```

### 3. 필드 주입
- **`@Autowired`****:** Spring Bean을 자동으로 주입할 때 사용되는 어노테이션입니다.
- **DAO 역할:** 데이터를 다루는 DAO 역할의 클래스는 `@Repository` 또는 `@Component` 어노테이션을 달아 Spring Bean으로 등록됩니다.

## ☁️ Git 사용법 및 협업 기본
### 1. 로컬 환경 설정 (Git Bash 사용)

| **명령어** | **설명** |
| --- | --- |
| `git config --global user.name "사용자 이름"` | Git 커밋에 사용할 사용자 이름 설정 |
| `git config --global user.email "사용자 이메일"` | Git 커밋에 사용할 사용자 이메일 설정 |
| **`git init`** | **현재 폴더를 로컬 저장소로 초기화** (`.git` 숨김 폴더 생성) |

### 2. 원격 저장소 연결

| **명령어** | **설명** |
| --- | --- |
| `git remote add origin [GitHub Repository 주소]` | 원격 저장소에 `origin`이라는 이름으로 주소를 등록 |
| **`vim .gitignore`** | **Git이 추적하지 않을 파일/폴더 목록**을 정의하는 파일을 생성/편집 (예: IDE 설정 파일, 빌드 결과물 등) |

> GitHub Repository: 원격 저장소내 프로젝트 폴더: 로컬 저장소
### 3. 파일 업로드 (Push)
1. **준비:** 업로드할 파일들을 준비합니다.
2. **메시지 준비:** 업로드할 때 적을 커밋 메시지를 준비합니다.
3. **업로드:** 원격 저장소로 보냅니다.

| **명령어** | **설명** |
| --- | --- |
| `git status` | 현재 로컬 저장소의 상태 확인 (수정된 파일, 스테이징되지 않은 파일 등) |
| **`git add .`** | 현재 폴더 내의 **모든 변경 사항을 스테이징 영역에 추가** (업로드 준비) |
| `git commit -m "커밋 메시지"` | 스테이징된 파일들을 **로컬 저장소에 저장**하고 커밋 메시지를 기록 |
| **`git push origin master`** | 로컬 저장소의 커밋을 **원격 저장소(****`origin`****)의 ****`master`**** 브랜치로 업로드** |

### 4. 파일 내려받기 (Clone)

| **명령어** | **설명** |
| --- | --- |
| **`git clone [GitHub Repository 주소]`** | 원격 저장소의 내용을 \*\*로컬로 복사(내려받기)\*\*하여 새로운 프로젝트 폴더를 만듭니다. |
