## 🔍 인덱스 (Index) 개념 정리
### 1. 인덱스의 기본 정의와 목적

| 구분 | 설명 |
| --- | --- |
| **개념** | 데이터베이스 테이블의 **색인(索引)**. 책의 목차나 찾아보기와 같은 역할. |
| **핵심 목적** | 원하는 데이터를 **빠르게 검색**하기 위해 사용. `SELECT` 쿼리의 성능을 극적으로 향상시킵니다. |
| **동작 원리** | 데이터가 저장된 물리적인 위치(포인터)를 미리 정렬된 형태로 저장해두고, 검색 시 이 인덱스 구조를 이용해 원하는 데이터를 바로 찾아갑니다. |

### 2. 인덱스의 장점과 단점

| 구분 | 장점 (Why use it?) | 단점 (Cost) |
| --- | --- | --- |
| **검색 속도** | `SELECT` 쿼리 성능 향상 (특히 데이터 양이 많을 때). \*\*트리 구조(B-Tree)\*\*를 사용하여 전체를 스캔하지 않고 빠르게 탐색합니다. | **저장 공간 증가** : 인덱스 자체도 별도의 공간에 저장됩니다. (DB 용량 증가) |
| **정렬/그룹화** | `ORDER BY`나 `GROUP BY` 같은 정렬/그룹화 작업의 속도가 향상됩니다. | **쓰기 성능 저하** : **`INSERT`**, **`UPDATE`**, **`DELETE`** 작업 시 인덱스 파일도 함께 수정되거나 재정렬되어야 하므로 성능이 느려집니다. |
| **중복 제어** | \*\*`UNIQUE INDEX`\*\*를 설정하면 데이터의 중복을 막을 수 있습니다. | **잦은 변경 비효율** : 삽입/수정/삭제가 잦은 컬럼에 인덱스를 걸면 오히려 성능이 악화될 수 있습니다. |

### 3. 인덱스의 내부 구조: B-Tree (기본)
대부분의 관계형 데이터베이스(MySQL, PostgreSQL 등)는 **B-Tree** 또는 이의 변형 구조를 인덱스로 사용합니다.
- **동작 원리**: 검색 시 데이터를 한 번에 절반씩 나누어 탐색하는 방식(이진 탐색과 유사). 예를 들어, 100만 건의 데이터에서 1건을 찾을 때, 인덱스가 없으면 100만 번의 연산이 필요할 수 있지만, B-Tree를 사용하면 몇 번의 연산만으로 빠르게 찾을 수 있습니다.
### 4. 인덱스 관련 SQL 명령어 (MySQL 기준)

| 목적 | SQL 구문 예시 | 설명 |
| --- | --- | --- |
| **일반 인덱스 추가** | `CREATE INDEX **idx_loginId** ON **member**(**loginId**);` | 가장 일반적인 인덱스 생성. |
| **일반 인덱스 추가 (ALTER)** | `ALTER TABLE **member** ADD INDEX **idx_loginId**(**loginId**);` | 테이블 구조를 변경하며 인덱스 추가. |
| **고유 인덱스 추가 (UNIQUE)** | `ALTER TABLE **member** ADD UNIQUE INDEX **uix_loginId**(**loginId**);` | 중복 값을 허용하지 않는 인덱스 생성. (가장 많이 사용) |
| **고유 제약조건 변경** | `ALTER TABLE **member** MODIFY COLUMN **loginId** VARCHAR(50) NOT NULL **UNIQUE**;` | 컬럼 정의 자체에 `UNIQUE` 제약조건을 추가. 인덱스 생성 효과를 가짐. |
| **인덱스 제거** | `ALTER TABLE **member** DROP INDEX **idx_loginId**;` | 테이블에서 인덱스만 제거. |

### 5. 인덱스 활용 및 분석 도구

| 명령어 | 용도 | 설명 |
| --- | --- | --- |
| **`EXPLAIN`** | **실행 계획 보여주기** | `SELECT` 문 앞에 붙여서 실행하면, 데이터베이스가 해당 쿼리를 어떤 순서와 방식으로 처리할지(특히 인덱스를 사용할지 여부) 상세히 보여줍니다. 인덱스 최적화의 기본입니다. |
| **`SHOW INDEX`** | **인덱스 목록 확인** | `SHOW INDEX FROM **member**;` 해당 테이블에 현재 걸려있는 모든 인덱스 정보를 보여줍니다. |

## 🔐 추가 개념: 암호화와 고유 식별자
### 1. 웹 개발에서의 암호화 (Hashing)

| 구분 | 설명 | 참고 |
| --- | --- | --- |
| **목적** | 사용자 비밀번호와 같이 민감한 데이터를 데이터베이스에 **복호화가 불가능한 형태로 저장**하기 위함입니다. | DB가 해킹되더라도 원본 비밀번호가 유출되는 것을 막습니다. |
| **알고리즘** | **MD5**, **SHA256**, **SHA512** 등은 데이터를 고정된 길이의 문자열(해시)로 변환하는 **단방향 암호화(Hashing)** 방식입니다. | SHA256이 MD5보다 훨씬 안전하여 현재 웹 개발에서 널리 사용됩니다. |

### 2. 고유 식별자 (UUID/ULID)

| 구분 | 설명 |
| --- | --- |
| **UUID (Universally Unique Identifier)** | 128비트 길이의 범용 고유 식별자(ID)입니다. 네트워크상의 모든 개체에 대해 고유성을 보장하기 위해 사용됩니다. |
| **용도** | ID를 **AUTO_INCREMENT** (자동 증가) 대신 사용하는 경우, 여러 서버에서 동시에 데이터를 삽입할 때 충돌 없이 고유한 ID를 생성할 수 있습니다. |
