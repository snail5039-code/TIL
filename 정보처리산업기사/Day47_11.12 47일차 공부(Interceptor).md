## 🚀 Interceptor (인터셉터) 정리 및 추가 정보
제공해주신 'Interceptor'와 관련된 내용을 단락별로 정리하고, 추가적인 정보를 보강하여 설명드리겠습니다.

---

### 1. Interceptor의 정의 및 역할
Interceptor는 웹 애플리케이션에서 **요청을 가로채서(Intercept)** 처리하는 핵심적인 역할을 수행합니다.
- **주요 기능:** 클라이언트의 요청이 \*\*컨트롤러(Controller)\*\*로 도달하기 전, 후, 그리고 최종적으로 뷰 렌더링이 완료된 후의 시점에 끼어들어(가로채서) 원하는 작업을 수행합니다.
- **활용 예시 (App):** 로그인 여부를 파악하여, 로그인이 필요한 기능에 대해 사용자가 로그인하지 않았다면 아예 **컨트롤러로의 접근을 차단**하는 데 사용됩니다. 로그인 검증을 통과하면 해당 요청을 적절한 컨트롤러로 전달합니다.

### 2. Interceptor의 가로채는 시점 (3가지 메소드)
Interceptor는 일반적으로 스프링 프레임워크에서 `HandlerInterceptor` 인터페이스를 구현하며, 요청 처리 흐름의 세 가지 주요 시점에 호출되는 메소드를 가집니다.

| **시점** | **메소드** | **역할 및 설명** |
| --- | --- | --- |
| **컨트롤러 실행 전** | `preHandle()` | 요청 처리 전에 실행되며, 주로 **인증/인가(로그인 여부)** 확인, 로깅, 요청 가공 등의 작업을 수행합니다. 여기서 `true`를 반환해야 다음 단계(컨트롤러)로 넘어갈 수 있습니다. |
| **컨트롤러 실행 후, 뷰 렌더링 전** | `postHandle()` | 컨트롤러가 작업을 마친 후 뷰(View)가 렌더링되기 전에 실행됩니다. 주로 응답 정보(모델)를 가공하거나 추가적인 정보를 삽입하는 데 사용됩니다. |
| **뷰 렌더링 후** | `afterCompletion()` | 모든 작업(뷰 렌더링 포함)이 완료된 후 **가장 마지막에** 실행됩니다. 주로 예외 발생 여부와 관계없이 사용된 리소스를 해제(자원 정리)하거나 최종 로깅 작업을 수행합니다. |

### 3. Filter (필터)와의 차이점
요청을 가로채는 역할은 비슷하지만, Filter는 Interceptor보다 더 넓은 범위에서, 더 낮은 레벨에서 작동합니다.
- **Filter (걸러내다):**
	- **작동 시점:** **서블릿 컨테이너** 레벨에서 작동하며, 요청이 가장 먼저 통과하는 문지기 역할입니다.
	- **주요 활용:** 인코딩 설정, **XSS(크로스 사이트 스크립팅) 방지** 필터, 보안 설정 등 요청/응답 자체를 가공하는 작업에 주로 사용됩니다.
	- **접근성:** Spring의 **DispatcherServlet** 이전 단계에서 작동하므로, Spring의 빈(Bean) 객체에 직접 접근하기 어렵습니다.
- **Interceptor:**
	- **작동 시점:** Spring의 **DispatcherServlet**이 컨트롤러를 호출하는 시점 주변(Spring Context 내부)에서 작동합니다.
	- **주요 활용:** 인증/인가, 권한 확인, 세부 로깅 등 **Spring의 컨트롤러 및 관련 객체**에 의존적인 작업에 적합합니다.
	- **접근성:** Spring의 모든 **빈(Bean)** 객체와 `ModelAndView` 객체에 쉽게 접근하고 조작할 수 있습니다.

### 4. 게시판 구현 관련 요구사항 정리
제시된 게시판 요구사항은 웹 UI 및 백엔드 데이터 구성에 관한 내용입니다.
### A. 데이터베이스 구성 (객체를 구성할 정보)
- **목적:** 객체 하나를 만들어서 편하게 사용하려는 목적으로, 필요한 정보를 객체에 담습니다.
- **구성 요소:**
	- `게시판` 테이블: **공지사항**, **자유게시판**, **질문과 답변** 3개의 게시판을 구성해야 합니다.
	- `게시글` 테이블: 각 게시판별로 최소 3개 이상의 게시글 데이터를 구성해야 합니다.
	- **세션 정보:** **로그인 여부**나 사용자 정보 등은 Interceptor의 로그인 검증을 통과한 후, 세션에서 가져와 게시글 작성 시 **작성자 정보** 등에 활용될 수 있습니다 (꼭 필요한 것은 아니지만, 실제 게시판 구현에 필수적).
### B. 사용자 인터페이스 (UI) 요구사항
- **2차 메뉴 (드롭다운):** 웹 페이지의 '리스트' 항목에 **마우스가 올라가면** (Hover 시) 그 밑으로 **게시판 3개**(`공지사항`, `자유게시판`, `질문과 답변`)가 드롭다운 형태로 펼쳐지는 메뉴를 구현해야 합니다.
- **기능 연결:** 해당 메뉴 항목을 **클릭**하면, 해당하는 게시판의 **게시글 리스트** 페이지가 사용자에게 보여지도록(URL 연결) 구현해야 합니다.

## 💻 Interceptor (인터셉터) 사용 예시 코드
제공해주신 내용을 바탕으로, 스프링 환경에서 가장 흔하게 사용되는 **로그인 검증 인터셉터**의 구현 예시 코드를 세 부분으로 나누어 제공해 드립니다.

---

### 1. Interceptor 구현체 코드: `LoginCheckInterceptor`
요청 처리 **전에** (preHandle) 사용자의 로그인 세션을 확인하여, 로그인이 되어 있지 않으면 특정 페이지로 리다이렉트(Redirect)하여 접근을 차단하는 핵심 로직입니다.
Java
```java
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import javax.servlet.http.HttpSession;

import org.springframework.web.servlet.HandlerInterceptor;
import org.springframework.web.servlet.ModelAndView;

// HandlerInterceptor 인터페이스를 구현합니다.
public class LoginCheckInterceptor implements HandlerInterceptor {

    // 1. 컨트롤러 실행 전 (preHandle)
    @Override
    public boolean preHandle(
        HttpServletRequest request, 
        HttpServletResponse response, 
        Object handler) throws Exception {

        String requestURI = request.getRequestURI();
        System.out.println("인터셉터 실행: " + requestURI);

        HttpSession session = request.getSession();
        
        // **로그인 여부 파악**
        // 세션에 "loginUser"라는 이름으로 사용자 객체가 있는지 확인
        if (session.getAttribute("loginUser") == null) {
            System.out.println("미인증 사용자 요청 -> 컨트롤러 접근 차단");
            
            // 로그인 페이지로 리다이렉트
            response.sendRedirect("/login?redirectURL=" + requestURI);
            
            // **false 반환: 컨트롤러 실행을 중단하고 요청 종료**
            return false;
        }

        // **true 반환: 로그인 검증 통과 -> 컨트롤러 실행**
        return true; 
    }

    // 2. 컨트롤러 실행 후, 뷰 렌더링 전 (postHandle)
    // 컨트롤러가 반환한 Model 정보를 조작할 때 사용됩니다.
    @Override
    public void postHandle(
        HttpServletRequest request, 
        HttpServletResponse response, 
        Object handler, 
        ModelAndView modelAndView) throws Exception {
        
        // 예시: postHandle에서는 특별한 작업을 하지 않고 생략 가능
    }

    // 3. 뷰 렌더링 후 (afterCompletion)
    // 예외 발생 여부와 관계없이 최종적으로 자원 정리가 필요할 때 사용됩니다.
    @Override
    public void afterCompletion(
        HttpServletRequest request, 
        HttpServletResponse response, 
        Object handler, 
        Exception ex) throws Exception {
        
        // 예시: 요청 처리 종료 후 로깅
        System.out.println("인터셉터 종료: 요청 처리 완료 및 자원 정리");
    }
}
```

### 2. Interceptor 등록 설정 코드: `WebConfig`
구현한 인터셉터가 어떤 URL 패턴에 적용될지 설정하는 코드입니다. 이 설정 클래스는 보통 `WebMvcConfigurer` 인터페이스를 구현합니다.
Java
```java
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.InterceptorRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        
        registry.addInterceptor(new LoginCheckInterceptor()) // 1. 인터셉터 등록
                .order(1) // 2. 인터셉터 실행 순서 지정 (낮을수록 먼저 실행)
                .addPathPatterns("/**") // 3. **전체 요청 경로에 적용**
                .excludePathPatterns( // 4. **인터셉터를 적용하지 않을 예외 경로 지정**
                    "/", "/login", "/logout", 
                    "/css/**", "/images/**", "/error" 
                );
        
        // **적용 시나리오:**
        // - "/board/list", "/item/detail" 등 모든 요청에 인터셉터가 적용됩니다.
        // - 하지만, 로그인 기능 자체인 "/login" 경로는 무한 루프에 빠지지 않도록 제외합니다.
    }
}
```

### 3. Controller 코드 (간단 예시)
인터셉터가 성공적으로 요청을 가로채고 통과시킨 후, 최종적으로 실행되는 컨트롤러입니다.
Java
```java
import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.ResponseBody;

@Controller
public class BoardController {

    // 이 요청은 LoginCheckInterceptor의 검증을 통과해야만 실행됩니다.
    @GetMapping("/board/write")
    @ResponseBody
    public String writeForm() {
        // 로그인 검증을 통과했으므로 안전하게 게시글 작성 로직 실행
        return "게시글 작성 폼 (로그인 사용자 전용)";
    }
    
    // 이 요청은 Interceptor의 excludePathPatterns에 의해 검증 없이 실행됩니다.
    @GetMapping("/login")
    public String login() {
        return "login/loginForm"; // 로그인 페이지 뷰 반환
    }
}
```
