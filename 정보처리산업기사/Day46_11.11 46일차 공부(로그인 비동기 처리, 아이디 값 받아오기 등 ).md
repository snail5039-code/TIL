## 🔑 로그인 및 로그아웃 처리
사용자가 아이디와 비밀번호를 입력하고 로그인 버튼을 누르는 과정은 다음과 같이 처리됩니다.
### 1. 로그인 처리 (인증)
- **아이디/비밀번호 검증:**
	- 사용자가 입력한 아이디와 비밀번호를 서버로 전송합니다 (일반적으로 **POST** 요청).
	- 서버는 해당 아이디를 가진 사용자를 DB에서 찾습니다.
	- DB에 저장된 **암호화된** 비밀번호와 사용자가 입력한 비밀번호를 비교합니다 (Spring Security 등을 사용하면 이 과정이 자동으로 처리됩니다).
- **성공 시:**
	- 로그인 처리를 진행하고 **세션(Session)** 또는 \*\*토큰(Token - JWT 등)\*\*을 발급하여 클라이언트에게 전달합니다.
	- 클라이언트는 이 정보를 보관하여 이후 요청 시 **자격 증명**으로 사용합니다.
	- 페이지를 메인 화면 등 지정된 위치로 이동시킵니다.
- **실패 시:**
	- 아이디 또는 비밀번호가 일치하지 않으면 **로그인 불가능 메시지**를 사용자에게 보여줍니다 (예: "아이디 또는 비밀번호가 잘못되었습니다.").
### 2. 로그아웃 처리
- 클라이언트가 로그아웃 버튼을 누르면 서버에 로그아웃 요청을 보냅니다.
- 서버는 해당 사용자의 **세션 정보를 무효화**하거나 **토큰을 블랙리스트**에 추가하여 더 이상 유효하지 않게 만듭니다.
- 사용자를 로그인 페이지 등으로 리다이렉션합니다.

## 📝 게시글 관련 기능 (인증/인가 활용)
### 1. 게시글 작성 시 로그인 필수화 (인증)
- **인증(Authentication) 체크:** 게시글 작성 페이지 접근 또는 작성 요청 시, 현재 사용자가 **로그인 상태**인지 확인해야 합니다.
- 로그인하지 않은 사용자가 게시글 작성을 시도하면 **로그인 페이지로 리다이렉션**되도록 설정합니다 (Spring Security에서 쉽게 설정 가능).
### 2. 작성자 정보 저장
- 로그인 후 게시글을 작성하면, 시스템은 현재 로그인한 사용자의 정보를 **세션**이나 \*\*보안 컨텍스트(SecurityContext)\*\*에서 가져올 수 있습니다.
- 게시글 저장 시, 현재 사용자의 \*\*회원 번호 (PK)\*\*를 `writer_id`와 같은 필드에 저장합니다. **절대** 사용자가 임의로 입력한 작성자 정보를 사용해선 안 됩니다.
### 3. 목록 및 상세 기능에서의 작성자 표시
- 게시글 목록 또는 상세 페이지를 보여줄 때, 게시글에 저장된 **작성자의 회원 번호**를 이용하여 회원 테이블에서 해당 회원의 **로그인 아이디**를 조회하여 사용자에게 보여줍니다.

## 🛡️ 권한 체크 (인가)
- \*권한 체크(Authorization)\*\*는 인증된 사용자가 특정 자원(예: 관리자 페이지, 다른 사람의 게시글 수정/삭제)에 접근하거나 기능을 실행할 **권한**이 있는지 확인하는 과정입니다.
### 예시: 게시글 수정/삭제 시 권한 체크
1. 사용자가 게시글의 **수정/삭제** 버튼을 누릅니다.
2. 서버는 요청을 받고, 현재 로그인된 사용자의 **회원 번호**를 가져옵니다.
3. 게시글의 **작성자 회원 번호**와 현재 로그인된 사용자의 **회원 번호**를 비교합니다.
	- **일치하는 경우:** 수정/삭제 권한이 있으므로 요청을 처리합니다.
	- **일치하지 않는 경우:** 권한이 없으므로 **접근 거부 메시지**를 반환하거나 에러 페이지로 리다이렉션합니다 (예: "권한이 없습니다.").
4. 만약 \*\*관리자 권한(ADMIN)\*\*을 가진 사용자라면, 작성자가 아니더라도 수정/삭제 권한을 부여하는 로직을 추가할 수도 있습니다.

## ⚡ 비동기(Ajax) 로그인 활용 및 예시
일반적인 로그인은 요청 후 페이지가 새로고침되지만, \*\*비동기 로그인 (Ajax)\*\*을 사용하면 페이지 이동 없이 백그라운드에서 인증을 처리하고 결과를 사용자에게 보여줄 수 있습니다.
### 간단한 비동기 로그인 예시 (프론트엔드)
JavaScript
```java
// HTML에서 ID와 Password 값을 가져온다고 가정
const userId = document.getElementById('userId').value;
const password = document.getElementById('password').value;

fetch('/api/login', { // 로그인 처리를 위한 API 엔드포인트
    method: 'POST',
    headers: {
        'Content-Type': 'application/json'
    },
    body: JSON.stringify({ // JSON 형식으로 데이터 전송
        username: userId,
        password: password
    })
})
.then(response => {
    // Spring Security를 사용하면 기본적으로 200 OK가 아닌 
    // 성공 시 리다이렉트 (302) 또는 실패 시 401 Unauthorized를 반환할 수 있음.
    // 여기서는 커스텀한 로그인 처리 API를 가정.
    if (response.ok) { 
        return response.json(); // 성공 응답을 JSON으로 파싱
    } else {
        // 실패 응답 (예: 401 Unauthorized)
        return response.json().then(error => {
            throw new Error(error.message || "로그인 실패");
        });
    }
})
.then(data => {
    // **로그인 성공**
    alert('로그인 성공! 환영합니다.');
    // 성공 후 처리: 모달 닫기, UI 업데이트, 페이지 리로드 등
    window.location.reload(); 
})
.catch(error => {
    // **로그인 실패**
    console.error('Login error:', error);
    document.getElementById('loginMessage').innerText = error.message; // 메시지 표시
});
```

### ➕ 추가할 내용: 비동기 환경과 Spring Security
Spring Framework에서 **Spring Security**를 사용하고 비동기(Async) 처리를 할 때 주의할 점이 있습니다.
1. **Ajax 로그인 응답 커스터마이징:**
	- 기본 Spring Security는 로그인 실패 시 HTML 에러 페이지로 리다이렉트하지만, 비동기(Ajax) 로그인에서는 **JSON 형식의 에러 메시지**를 반환하도록 `AuthenticationFailureHandler`를 커스터마이징 해야 합니다.
2. **비동기 스레드와 보안 컨텍스트:**
	- `@Async`나 `CompletableFuture` 등을 사용하여 **새로운 비동기 스레드**에서 작업을 수행할 경우, 기본적으로 현재 로그인된 사용자 정보가 담긴 \*\*보안 컨텍스트(SecurityContext)\*\*가 새로운 스레드로 전파되지 않습니다.
	- 이 문제를 해결하려면 Spring Security 설정에서 \*\*`SecurityContextHolderStrategy`\*를 **`MODE_INHERITABLETHREADLOCAL`** 등으로 설정하거나, \*\*`DelegatingSecurityContextExecutor`\*를 사용하여 보안 컨텍스트를 수동으로 전파해야 합니다. (이것은 고급 내용이므로 당장 필수는 아닙니다.)
