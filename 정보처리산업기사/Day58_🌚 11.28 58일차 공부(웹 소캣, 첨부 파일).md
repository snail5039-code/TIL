## 🚀 스프링 부트 웹소켓 (WebSocket)
웹소켓은 하나의 **TCP 연결**을 통해 클라이언트와 서버 간에 **전이중(Full-Duplex)** 통신을 가능하게 하는 프로토콜입니다. HTTP 요청/응답 주기 없이 실시간으로 데이터를 주고받을 수 있어 채팅, 게임, 실시간 알림 등에 유용합니다.
### 💡 주요 추가 설명
1. **의존성 추가:** 스프링 부트에서 웹소켓을 사용하려면 언급하신 대로 `spring-boot-starter-websocket` 의존성을 추가합니다.
	- **Maven:**XML
		
	```javascript
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-websocket</artifactId>
</dependency>
	```
	
2. **구성 (Configuration):** 웹소켓 활성화 및 엔드포인트 설정을 위해 `WebSocketMessageBrokerConfigurer`를 구현하는 설정 클래스가 필요합니다. 이는 STOMP(Simple Text Oriented Messaging Protocol)를 사용하여 메시지 브로커 기능을 추가할 때 일반적입니다.Java
	
	```javascript
import org.springframework.context.annotation.Configuration;
import org.springframework.messaging.simp.config.MessageBrokerRegistry;
import org.springframework.web.socket.config.annotation.EnableWebSocketMessageBroker;
import org.springframework.web.socket.config.annotation.StompEndpointRegistry;
import org.springframework.web.socket.config.annotation.WebSocketMessageBrokerConfigurer;

@Configuration
@EnableWebSocketMessageBroker
public class WebSocketConfig implements WebSocketMessageBrokerConfigurer {

    @Override
    public void configureMessageBroker(MessageBrokerRegistry config) {
        // 서버 -> 클라이언트로 메시지 발송 시 prefix
        config.enableSimpleBroker("/topic"); 
        // 클라이언트 -> 서버로 메시지 수신 시 prefix (Controller @MessageMapping에서 사용)
        config.setApplicationDestinationPrefixes("/app");
    }

    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry) {
        // 웹소켓 연결을 위한 엔드포인트 설정
        registry.addEndpoint("/ws-connect").withSockJS(); 
    }
}
	```
3. **컨트롤러 (@Controller):** `@MessageMapping`을 사용하여 특정 경로로 들어오는 STOMP 메시지를 처리합니다.Java
	
	```javascript
import org.springframework.messaging.handler.annotation.MessageMapping;
import org.springframework.messaging.handler.annotation.SendTo;
import org.springframework.stereotype.Controller;

@Controller
public class ChatController {

    @MessageMapping("/chat.sendMessage") // "/app" + "/chat.sendMessage" 경로로 메시지 수신
    @SendTo("/topic/public") // 메시지를 "/topic/public"을 구독하는 클라이언트에게 송신
    public ChatMessage sendMessage(ChatMessage chatMessage) {
        return chatMessage;
    }

    // 간단한 메시지 DTO 예시
    public static class ChatMessage {
        private String content;
        private String sender;
        // Getters, Setters...
    }
}
	```

## 💾 MyBatis @Mapper를 이용한 DAO 직접 쿼리
MyBatis에서 XML 매퍼 파일을 사용하지 않고, **DAO 인터페이스**에 **어노테이션**을 사용하여 직접 SQL 쿼리를 작성하는 방식을 **Mapper Interface** 방식이라고 합니다. 이 방식은 간단한 쿼리에 매우 효율적이며, XML 파일 관리의 번거로움을 줄여줍니다.
### 💡 주요 추가 설명
1. **어노테이션 종류:**
	- **`@Select`**: SELECT 쿼리 작성 시 사용.
	- **`@Insert`**: INSERT 쿼리 작성 시 사용.
	- **`@Update`**: UPDATE 쿼리 작성 시 사용.
	- **`@Delete`**: DELETE 쿼리 작성 시 사용.
	- **`@Options`**: INSERT 시 **Auto-Generated Key**를 반환받을 때 사용 (예: `useGeneratedKeys = true`, `keyProperty = "id"`).
2. **동적 쿼리 처리:** 복잡한 `if`, `where`, `foreach` 등의 동적 쿼리가 필요할 때는 **`@SelectProvider`****, ****`@InsertProvider`** 등의 **Provider 어노테이션**을 사용하거나, 여전히 XML 매퍼 파일을 사용하는 것이 더 관리하기 쉽습니다. 하지만 간단한 동적 쿼리는 **Java String Manipulation**이나 **OGNL**을 쿼리 내에서 제한적으로 사용할 수도 있습니다.
3. **매개변수:** 메서드 인자는 **`@Param`** 어노테이션을 사용하여 쿼리 내에서 사용할 이름을 지정할 수 있습니다.
### 💻 코드 예시
다음은 `@Mapper`를 사용하고 어노테이션으로 쿼리를 직접 작성하는 DAO(Mapper Interface)의 예시입니다.
Java
```javascript
import org.apache.ibatis.annotations.Delete;
import org.apache.ibatis.annotations.Insert;
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Options;
import org.apache.ibatis.annotations.Param;
import org.apache.ibatis.annotations.Select;
import org.apache.ibatis.annotations.Update;

// 스프링이 빈으로 등록할 수 있도록 @Mapper 어노테이션 사용
@Mapper
public interface UserMapper {

    // 1. SELECT 예시
    // @Param으로 쿼리에서 사용할 파라미터 이름을 지정합니다.
    @Select("SELECT id, username, email FROM users WHERE id = #{userId}")
    User findUserById(@Param("userId") Long id);

    // 2. INSERT 예시 (자동 생성 키 받기 포함)
    @Insert("INSERT INTO users (username, email) VALUES (#{user.username}, #{user.email})")
    @Options(useGeneratedKeys = true, keyProperty = "id") // DB에서 자동 생성된 키를 User 객체의 'id' 필드에 설정
    int insertUser(@Param("user") User user);

    // 3. UPDATE 예시
    @Update("UPDATE users SET username = #{user.username}, email = #{user.email} WHERE id = #{user.id}")
    int updateUser(@Param("user") User user);

    // 4. DELETE 예시
    @Delete("DELETE FROM users WHERE id = #{userId}")
    int deleteUser(@Param("userId") Long id);
}

// User DTO 예시 (Getter/Setter 생략)
public class User {
    private Long id;
    private String username;
    private String email;
    // ...
}
```

📎 첨부파일 (File Upload) 처리
### 1. 의존성 (Dependency) 확인
스프링 부트의 기본 내장 톰캣은 파일 업로드를 처리할 수 있지만, 만약 레거시 환경에서 서블릿 3.0 이전의 방식이나 특정 설정을 사용한다면 추가적인 의존성(`commons-fileupload` 등)이 필요할 수도 있습니다. **대부분의 스프링 부트 환경에서는 별도의 의존성 추가 없이** 바로 사용 가능합니다.
### 2. 설정 (Configuration)
대용량 파일 업로드 시 필요한 최대 크기 설정 등은 `application.properties` 또는 `application.yml` 파일에서 설정합니다.
Properties
```javascript
# application.properties 예시
# 최대 파일 하나의 크기: 10MB
spring.servlet.multipart.max-file-size=10MB 
# 한 번의 요청으로 전송 가능한 전체 크기: 100MB
spring.servlet.multipart.max-request-size=100MB
```

### 3. Controller 코드: 파일 업로드 처리
스프링에서 파일 업로드는 주로 **`MultipartFile`** 객체를 사용하여 처리합니다. 클라이언트에서 파일을 전송할 때는 `<form enctype="multipart/form-data">`를 사용해야 합니다.
Java
```javascript
import java.io.File;
import java.io.IOException;
import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.multipart.MultipartFile;

@Controller
public class FileUploadController {

    private final String uploadPath = "/path/to/upload/directory/"; // 실제 저장 경로로 변경해야 합니다.

    @PostMapping("/upload")
    public String handleFileUpload(@RequestParam("file") MultipartFile file) {

        if (file.isEmpty()) {
            // 파일이 비어있는 경우 처리
            return "redirect:/uploadFailure";
        }

        try {
            // 1. 파일 이름 가져오기
            String originalFileName = file.getOriginalFilename();
            
            // 2. 저장할 파일 경로 및 파일 객체 생성
            File dest = new File(uploadPath + originalFileName);

            // 3. 파일 저장 (실제 디스크에 기록)
            file.transferTo(dest); 

            // **여기서 파일 정보를 DB에 저장합니다.**
            // DB에 저장할 정보: 원본 파일명, 서버 저장 경로, 파일 크기 등

            return "redirect:/uploadSuccess";

        } catch (IOException e) {
            e.printStackTrace();
            return "redirect:/uploadFailure";
        }
    }
}
```

### 📌 핵심: DB 저장과 `MultipartFile`
파일을 업로드할 때, 파일을 \*\*실제 서버 디스크 (혹은 S3 같은 클라우드 스토리지)\*\*에 저장하고, **파일에 대한 메타 정보** (원본 이름, 저장된 이름, 경로, 크기 등)를 **MyBatis를 이용해 DB에 저장**해야 합니다.
예를 들어, DB에 파일 메타 정보를 저장하는 MyBatis DAO 코드는 다음과 같이 작성할 수 있습니다.
Java
```javascript
// 파일 메타 정보 DTO
public class FileInfo {
    private Long id;
    private String originalFileName;
    private String serverPath;
    private Long size;
    // ...
}

@Mapper
public interface FileMapper {

    @Insert("INSERT INTO file_info (original_file_name, server_path, size) " +
            "VALUES (#{file.originalFileName}, #{file.serverPath}, #{file.size})")
    @Options(useGeneratedKeys = true, keyProperty = "id")
    int insertFileInfo(@Param("file") FileInfo fileInfo);
}
```

컨트롤러에서 `file.transferTo(dest);` 실행 후, `FileInfo` 객체를 생성하여 \*\*`FileMapper.insertFileInfo()`\*\*를 호출하면 됩니다.
